# 2 段階 RAG (EmbeddingGemma 2 + d1-3B) の検証

- 検証日: 2026-10-26
- 実行環境: Mac mini (Apple M2 Pro / 32GB)、PyTorch 2.14.1 + transformers 5.20.2、MPS
- 埋め込み: `google/embeddinggemma-2` (テキストのみ、fp32、768 次元)
- 判断: `LiquidAI/d1-3B` (bf16、`system_one`)

## 1. 目的

キャラクターのセリフを LLM に書かせるとき、そのキャラクターの経験・思い出・知識から「この場面で思い出す記憶」を渡したい。
埋め込みの類似度だけで選ぶ RAG では、場面に効く記憶を引き出せないことがあった。そこで、

1. EmbeddingGemma 2 (以下 EG2) で候補を多めに取り、
2. 判断モデル d1-3B で候補に優先順位を付け直す

2 段階の方式が、類似度だけの方式よりどれだけ記憶を引き出せるかを確かめた。

## 2. 結論

| 方式 | 必須の再現率@3 | 全必須@3 | 適合率@3 | nDCG@5 | 時間 (1 場面) |
|---|---|---|---|---|---|
| EG2 のみ | 0.500 | 0.417 | 0.319 | 0.446 | 0.16 秒 |
| EG2 → d1 (3 段階) | 0.729 | 0.583 | 0.417 | 0.605 | 約 7 秒 |
| EG2 → d1 (選択) | 0.667 | 0.542 | 0.389 | 0.541 | 約 2.2 秒 |
| **EG2 → d1 (3 段階 + 選択)** | **0.771** | **0.625** | **0.444** | **0.632** | 約 9 秒 |

- **2 段階にすると、上位 3 件に必須の記憶が入る割合が 0.50 から 0.77 に上がる。** 場面に直接関係する記憶 (direct) は 0.62 → 0.94、言葉は一致しないが効いてくる記憶 (indirect) は 0.50 → 0.71。
- **判断モデルへの問い方が決め手。** 「この記憶を思い出すのは自然か」を yes/no で問うと、ボブとの懐かしい思い出に一律に「はい」と答え、EG2 単独より悪くなった (再現率@3 0.44)。「関係ない / 背景として頭にある / セリフに直接表れる」の 3 段階で問うと区別できる。候補を選択肢として並べて 1 つ選ばせる問い方も効き、2 つを足すと最もよい。
- **EG2 の検索文は 3 通りを統合する。** 場面すべて・直前のセリフと意図・意図だけの 3 つの検索文の順位を RRF で統合すると、上位 20 件に必須の記憶が入る割合が 0.79 → 0.90 になる (2 段目で取り戻せる上限が上がる)。EG2 は検索文に「ボブ」があると、ボブの出てくる記憶をどの場面でも上位に出す。
- **課題は速さ。** PyTorch (MPS) で 1 場面 約 9 秒かかり、セリフを 1 行ずつ生成する用途にはそのままでは遅い (5 章)。

## 3. 方法

### 3.1 データ (`data/`)

架空のドラマ「放課後の約束」のアリス (高校 2 年、幼なじみのボブが大阪へ転校する) の記憶 60 件と、アリスが次に話す場面 24 件。

- 記憶: 種類 (経験 / 思い出 / 知識 / 関係 / 好み・習慣)、関わる人物、時期、本文 (1〜2 文)。言葉は一致するが関係のない記憶 (「大阪」の家族旅行、「迷子」の修学旅行、「転校」の手続き) と、言葉は一致しないが場面に効く記憶 (転校した友達に手紙を書いたが返事が 1 回しか来なかった) を意図して混ぜた。
- 場面: 場面の説明、直前のやりとり、アリスが次に話す意図 (台詞計画の「意図」にあたる)。必須の記憶 (1〜2 件) と、出てきても構わない記憶を付けた。種類は direct 8 / indirect 12 / distractor 3 / broad 1。

### 3.2 方式

| 段 | 内容 |
|---|---|
| 検索 | 記憶は `title: アリスの{種類} \| text: （{時期}・{人物}）{本文}`、検索文は `task: search result \| query: ...` で埋め込み、コサイン類似度で並べる。検索文 3 通り (場面すべて / 直前のセリフ + 意図 / 意図だけ) の順位を RRF (k=60) で統合し、上位 20 件を候補にする |
| 判断 (3 段階) | 状態に登場人物と場面を入れ、候補ごとに `score` の質問「次の記憶は、この場面でのアリスの次のセリフにどのくらい関係するか」を問う。期待値 (0〜2) を 0〜1 にする |
| 判断 (選択) | 候補 20 件と「どれも関係しない」を選択肢にした `choice` の質問 1 つ。各候補の確率を使う |
| 統合 | 3 段階の値と選択の確率を足して並べ替え、上位 3 件をセリフ生成に渡す想定 |

### 3.3 指標

- 必須の再現率@k: 上位 k 件に入った必須の記憶の割合
- 全必須@3: 必須の記憶がすべて上位 3 件に入った場面の割合
- 適合率@3: 上位 3 件のうち、必須または「出てきても構わない」記憶の割合
- nDCG@5: 必須を 2、構わないを 1 として計算

## 4. 結果の詳細

検索文ごとの EG2 の必須の再現率 (@3 / @20):

| 検索文 | @3 | @20 |
|---|---|---|
| 場面すべて | 0.500 | 0.792 |
| 直前のセリフ + 意図 | 0.521 | 0.771 |
| 意図だけ | 0.583 | 0.771 |
| 3 通りを統合 | 0.500 | **0.896** |

場面の種類ごとの必須の再現率@3:

| 種類 | 件数 | EG2 のみ | 3 段階 | 選択 | 3 段階 + 選択 |
|---|---|---|---|---|---|
| direct | 8 | 0.62 | 0.94 | 0.81 | 0.94 |
| indirect | 12 | 0.50 | 0.71 | 0.67 | 0.71 |
| distractor | 3 | 0.17 | 0.33 | 0.17 | 0.50 |
| broad | 1 | 0.50 | 0.50 | 1.00 | 1.00 |

うまくいかなかった場面:

- 「本当に大阪に行けるか、現実的に考える」(s10): 必須は「新幹線の料金」と「バイトで貯めたお金」。料金は拾えたが、貯金は判断モデルが関係を見抜けなかった。2 つの記憶を組み合わせて初めて意味が出る場面は苦手。
- 「素直になれず、はぐらかす」(s08): 必須は母の口癖「言いたいことは、言えるうちに言いなさい」。判断モデルはボブ本人についての記憶を優先した。

その他の試行 (結果は `results/` に残していない初回の実行):

- yes/no の質問「この記憶を思い出したり踏まえたりするのは自然か」は、候補 20 件で再現率@3 0.44、全 60 件に問っても 0.40。EG2 単独 (0.50) より悪い。
- 3 段階 + 選択に、さらに EG2 の順位を RRF で混ぜると 0.73 に下がる。

## 5. 速さ

| 処理 | 時間 |
|---|---|
| EG2: 記憶 60 件の埋め込み | 1.1 秒 (初回のみ。以後は追加した記憶だけ) |
| EG2: 検索文 3 通りの埋め込み | 0.16 秒 |
| d1: 3 段階 × 20 件 | 約 7 秒 |
| d1: 選択 1 問 (20 件) | 約 2.2 秒 |

d1 は、候補ごとの質問が状態を共有していても、質問文と選択肢 (1 問 80 トークン前後) を 20 回読むので遅い。Rust への移植では、状態を読んだ後の内部状態 (LFM2 の畳み込みの状態と attention の KV) を使い回し、質問ごとに短い部分だけを計算する作りにする。それでも足りなければ、選択だけの軽い方式 (再現率@3 0.67、約 2 秒) に切り替えられるようにする。

## 6. 制約

- **データとラベルは検証者 (Claude) が作った。** 記憶・場面・正解のどれも同じ人が作っているので、判断モデルに有利な偏りがあり得る。人が作った場面で確かめ直したい。
- **規模が小さい。** 場面 24 件なので、1 場面で再現率@3 が約 4 ポイント動く。キャラクターは 1 人、言語は日本語だけ。
- 日本語の検索で EG2 より強い ruri-v3 とは比べていない。
- 選んだ記憶でセリフが良くなるかどうか (生成まで通した評価) はまだ確かめていない。
